# 独立问答评测 v2

10 份公开 PDF、1103 页、40 题。题目、答案要点、预设支持页与 PDF 指纹在生成回答前冻结。对照旧导入 PDF、v1 和分包复测文件核验指纹并排除重复。样本包含预公告稿、政府采购商务文件和设备采购文件。题型含 15 道单处事实、15 道多证据、10 道证据不足题。部分多要点题的证据位于同一页。

对比普通向量 RAG、现有 Agent 和 BM25 + 向量 RRF。共享 MinerU 解析结果，回答模型统一为 deepseek-v4.1-flash，向量模型为 qwen3.7-text-embedding-flash。应用代码基于 629b5b9，运行并发数为 4。三种流程的提示词及工具路径不同，因此比较的是整套问答流程。

## 错例与评测边界

- **d02-06**。第 6 页明示采购包 1 不允许合同分包，Agent 返回待核对，但其工具证据已含该条。这属于规则漏识别。评委却把这次拒答和引用分别标为恰当与支持，因此不能把自动引用分数当作人工核对结果。
- **d10-23**。问题同时问合同期限、分包和有效期。Agent 只进入分包专用路径并返回待核对，另外两个子问没有作答。适合优先检查复合问题的路由。
- **d06-14**。工具给出了第 12 页保证金金额，但 Agent 报告拿不到可引用编号，最后未作答。需要核对工具结果与证据编号传递。
- **d01-01**。第 4 页采购标的一览表写 11,100,000 元，第 236 页报价表另写 11,169,642.9 元。冻结金标只认第 4 页，混合 RAG 实际报告了两个值。应保留这个版本的原始分数，下一轮将这类题预先标成冲突题。
- **d04-12**。冻结题目限定商务部分，但同一 PDF 后部还含采购需求，评委指出第 90 页已有保洁员配置。这个题的范围设定容易误读，原始计分保留。10 道证据不足题不能当作 10 道经专家复核的拒答基准。
- 本次 Agent 在简单题和多证据题的完整正确数均未超过普通向量 RAG，且耗时更长。这个样本支持优先优化复合题路由、专用规则覆盖与工具引用传递。后续修改用本轮做回归，另选文件验证泛化。

## 问答路由实验与五文件复核

- 单次检索快路径未默认启用。试跑落盘 6/15 后，Windows 替换结果文件时发生权限错误。已保存的 d01-01 只报第 4 页金额，漏了第 236 页不同值。这一错误足以阻止默认启用，且不能从未完成的试跑估算总体提速。
- 复合题实验完成 15/15，模型初判完整正确 11/15，参考轮为 12/15。只有 d10-23 实际走了拆分，其余变化来自整题问答的重复运行。该题两次拆分实跑分别为 4.38 秒和 17.15 秒，参考轮 15.31 秒。保留受限拆分是为了把项目级分包与其余问题分开展示，并为两组结论分别挂引用。条件不满足时沿用整题处理。
- 最终通过产品问答入口在五份文件复核 d02-06、d06-14、d10-23、d01-01、d31-38。旧评分口径初判五题都完整正确；按冲突题口径，d01-01 仍未同时报告两处限价。其余四题均作答并给出支持引用。d10-23 的分包部分引用第 7、38 页，合同期和投标有效期在另一组引用中。
- 冻结金标与旧统计保留。另行复核 d01-01 时以“报告两个值并附两处引用”为准；d07-20 明确指出无法由包预算和浮动率上限算出具体水果单价，且说清缺少具体基准价，应视为恰当拒答。两条复核不改写原分数。

## 复现

按 [冻结清单](../eval/holdout_v2.json) 的 URL 与 SHA-256 获取原件，导入后创建文档 ID 映射。原始 PDF、问答证据、向量及本地 ID 留在忽略目录。

```powershell
python eval/compare_holdout.py --manifest eval/holdout_v2.json --mapping data/holdout-v2/mapping.json --output data/holdout-v2/run-new.json --embedding-model qwen3.7-text-embedding-flash --workers 4
python eval/summarize_holdout_v2.py eval/holdout_v2.json data/holdout-v2/run-new.json
```

运行器遇到请求错误时退出码为 1，并保留完整报告供汇总。v2 使用语义评分；首次运行的旧正则字段是占位数据，不参与统计。
